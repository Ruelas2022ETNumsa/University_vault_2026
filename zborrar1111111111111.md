**Contexto del proyecto**

Programa en Assembler MASM 5.0 para Intel 8086 en modo real, ejecutado en DOSBox. El enunciado indica trabaja en `.asm` puro con segmentos explícitos al estilo:

```asm
pila    SEGMENT PARA STACK 'STACK'
        DW 64 DUP(0)
pila    ENDS

datos   SEGMENT PARA 'DATA'
...
datos   ENDS

codigo  SEGMENT PUBLIC 'code'
program PROC FAR
        ASSUME SS:pila, DS:datos, CS:codigo
        PUSH DS
        SUB  AX, AX
        PUSH AX
        MOV  AX, datos
        MOV  DS, AX
```

---

**Enunciado**

En la cabecera IPv4 se incluyen las direcciones de red de origen y destino, pero no las máscaras de red. Un IP como `192.168.1.10/24` y `192.168.1.10/27` son iguales en la cabecera porque solo aparece `192.168.1.10`. Desarrollar un sistema que permita saber si una IP pertenece a una red clase A, B o C, o es una subred.

---

**Decisiones ya tomadas**

- Se trabaja con el modelo clásico de direccionamiento por clases.
- El dato de entrada es la IP como string en el segmento de datos, por ejemplo `'192.168.1.10'`.
- Solo se necesita el primer octeto (leer hasta el primer `.`), convertirlo a binario y comparar:

```
1  – 126  → Clase A
128 – 191  → Clase B
192 – 223  → Clase C
224 – 255  → Subred / fuera de rango clásico
```

- Las comparaciones son dos `CMP` + tres `JBE`, sin división ni máscaras.
- Queda pendiente definir: ¿entrada fija en datos o por teclado?, ¿salida en `B800h` directo?


Sí, tres cosas que van a aparecer sí o sí:

---

**1. El 127 es un caso especial** `127.x.x.x` es loopback, técnicamente no es Clase A válida aunque cae en el rango 1–126. Decidir ahora si se reporta como Clase A o como caso especial, para no tener que rehacer la lógica después.

---

**2. Conversión string → número del primer octeto** Hay que restar `'0'` (30h) a cada dígito y acumular con multiplicación por 10. En 8086 eso es `AAM` o `MUL` con la constante 10. Es el único procesamiento no trivial del programa, vale tenerlo claro antes de escribirlo. El primer octeto puede tener 1, 2 o 3 dígitos, así que el bucle lee hasta encontrar `.` (2Eh).

---

**3. Validación de la IP** ¿Qué hace el programa si le llega `999.1.1.1` o una cadena que no es una IP? Si el docente solo va a probar con IPs válidas no hace falta, pero si hay que ser robusto conviene decidirlo ahora porque afecta el flujo de `LeerCadena` o el parsing.

---

De las tres, la **2** es la más importante porque es el núcleo del programa. Las otras dos son decisiones de alcance que es mejor cerrar antes de codificar.

---

**Plan de trabajo**

---

**Fase 1 — base funcional (2 clases)**

Objetivo: programa que corre, muestra algo en pantalla y clasifica correctamente.

- IP fija en datos: `'128.10.1.1'`
- Parsear solo el primer octeto (bucle hasta `.`)
- Conversión string → número
- Comparar solo Clase A vs Clase B (dos `CMP`, dos `JBE`)
- Mostrar resultado en `B800h` con texto fijo: `'Clase A'` o `'Clase B'`

Cuando esto funciona tienes el esqueleto completo y el parsing validado.

---

**Fase 2 — las 4 categorías**

- Agregar Clase C y Subred a las comparaciones
- Agregar el caso `127` si se decide tratarlo especial
- Probar con una IP de cada clase cambiando el string en datos

---

**Fase 3 — entrada por teclado**

- Reemplazar IP fija por lectura del BDA (`0040h`) igual que en P3A
- El parser ya existe de la Fase 1, solo cambia de dónde viene el string

---

**Fase 4 — validación (opcional según docente)**

- Detectar primer octeto `0` o `> 255`
- Detectar string que no tiene el formato correcto

---

La Fase 1 es la única que puede sorprender, específicamente la conversión string → número. Todo lo demás se construye encima de eso sin cambios estructurales.
